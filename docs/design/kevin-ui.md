# Kevin：天线狗与工作空间

状态：第一版可交互设计与局部 Web 接入，尚未作为完整产品验收。组件入口：`/ui/?design`；成果工作台入口：`/ui/?design=workspace`。

## 设计方向

角色沿用用户认可的天线狗简笔画：宽圆脸、短折耳、两只正常眼睛、黑色侧脸、琥珀黄脸颊和短弯天线。**单眼 K 方案已被用户否决，不用于组件或品牌。** 原始草稿留在 `assets/design-drafts/`。

README 头图使用 `assets/kevin-head-handdrawn-v1.png`：从认可的 `kevin-doodle-antenna-v1.png` 提取的手绘头像，保留宽圆脸、大鼻子、折耳与蜡笔笔触。浅深色头图内嵌同一张透明 PNG，保持居中排版；不要再用几何重绘替代品牌主视觉。

UI 小尺寸 SVG 是面向缩放和动效的几何化版本，不是原图的逐像素复刻。手绘表情承担品牌识别，表单、代码与审批内容保持清晰的常规排版。无需用整页手写字体模拟亲切感。

| --- | --- | --- |
| 页面纸色 | #F6F2E9 | #25241F |
| 卡片纸色 | #FFFDF8 | #302E28 |

琥珀色用作装饰、动作信号和强调底色，避免浅黄色小字。成功与错误另用语义色，并同时提供文字。正文使用 Avenir Next / 苹方 / 微软雅黑，标题适度使用宋体，品牌字使用可用的手写字体回退；无需请求外部字体。

基础间距 4 / 8 / 12 / 16 / 24 / 32 / 48；卡片圆角 14–16px；按钮最小高度 40px；键盘焦点使用独立 3px 描边。减少动效偏好关闭角色动画与过渡。小头像保持 SVG 清晰，但状态必须搭配文字，不能要求用户辨认细小表情。

## 角色状态与接入

| 状态 | 动作 | 当前接入 |
| --- | --- | --- |
| 待命 | 自然垂耳、双眼正视 | 会话空闲 |
| 倾听 | 短折耳抬起、轻歪头 | 仅预览；未实现麦克风监听 |
| 思考 | 耳朵收拢、天线缓摆（2.8s） | 会话忙碌且无进行中的工具事件 |
| 执行 | 双耳后收、天线亮度脉冲（1.5s） | 最新工具事件为 opening/running 且会话忙碌 |
| 完成 | 眯眼笑、耳朵弹动一次（0.6s） | 仅预览；不能用 busy=false 推断任务成功 |
| 待确认 | 单耳半抬、头歪向另一侧 | 有待审批请求，优先于忙碌状态 |
| 需要处理 | 停止动作、天线低垂 | 仅预览；现有错误消息照常展示 |

动态幅度小，不移动整体布局。入口处强调一次动作，持续状态只保持轻微天线变化。真实界面没有自动制造倾听、成功或失败状态。

## README 风格

双语 README 使用同一套浅深响应式 SVG 头图：天线狗、kevin 字标、墨黑文字、琥珀下划线。头图下先说产品是什么，再给入口和现有能力。减少装饰 emoji，保留 CI、开发预览、安装要求、支持矩阵与路线图。界面截图明确标注示例数据，不把设计草图当成已经交付的产品能力。

## 第二版：以成果为中心的工作台

用户反馈旧版“侧栏＋聊天气泡”过于传统。第二版将主要交互对象从消息流改为持续存在的工作成果：

1. **意图区**：目标与关键约束始终可见，狗狗给出当前状态和一句解释。
2. **阶段路径**：理解目标 → 形成草稿 → 等你确认 → 收好成果。在原型中允许点击切换，正式产品中必须由运行时真实事件驱动。
3. **材料区**：点击来源卡片查看摘录；当前仅使用明确标注的示例内容，不伪装成实际仓库检索结果。
4. **成果区**：草稿原地展开，可以直接修改标题和介绍，修改立即在本地显示。成果不会被新的聊天消息冲走。
5. **决策区**：阶段相关的确认便签，支持确认或退回修改。生产接入前需绑定真实差异、影响范围和审批 ID。
6. **随时补充**：输入内容进入持久于当前页面会话的约束列表与讨论记录；原型明确提示尚未自动改写草稿。刷新会重置，不声称具备持久化。

组件 `WorkCanvas` 管理局部演示状态；`WorkCanvasPreview` 提供独立的全屏入口与主题切换；样式位于 `work-canvas.css`。主应用的会话协议、审批流程不因设计原型而改写。

窄屏按材料 → 成果 → 决策 → 补充的顺序排列，不要求拖拽或横向移动画布。用户可以用键盘操作原生按钮与表单。尊重减少动效偏好。

这不是为所有任务强制套用文档：后续代码任务可以以差异为主成果，研究任务以结论和证据为主成果；简单问答则只需紧凑回答，不必创建整张工作台。

第二版验证：Web TypeScript 与 Vite 构建通过；Chrome 交互检查覆盖材料摘录、标题即时编辑、补充约束与讨论记录、确认、退回修改、阶段切换、重置、浅深主题、320px/390px 布局和减少动效。未出现 pageerror；桌面/手机截图已检查。README 图片来自本地交互原型，未接入真实任务执行。

## App 界面基线（2026-10-27）

默认 `/ui/` 现在使用产品工作空间布局，保留上述两个设计预览入口。

- `AppSidebar` 负责导航和新对话；`App` 负责视图组合、会话连接及工作过程面板开关。
- `ChatThread` 负责欢迎、消息、审批、输入和停止；继续复用 `createAgentSession`，不在组件中增加模型或工具执行逻辑。
- `app-shell.css` 只作用于产品壳层，不改变设计预览。品牌和欢迎使用原始手绘 PNG，小尺寸状态继续使用现有 SVG 与文字。
- 欢迎页的三个入口只填入输入框并聚焦，不自动执行。审批始终在对话主线；工作过程默认折叠，在窄屏可切换查看。
- 当前“新对话”清空本地会话并重置运行关联；运行记录并非可恢复的会话列表。不展示虚构的最近会话或工具执行结果。

### Web 到桌面 App

先完成 Web 产品交互，再选定桌面宿主。Web 拥有视图、交互和状态展示；host 拥有模型配置、运行和持久化；未来桌面层负责启动/停止本地 host、文件选择、系统权限、通知及窗口生命周期。模型密钥与工具执行不移入 WebView。

下一轮产品工作包括会话持久化与恢复、Markdown/代码/成果展示、结构化工作进度以及更面向个人用户的设置页。这些功能应先定义 host 合同，再接 UI；目前保留已有任务、运行记录和设置功能。桌面打包、原生桥接和原生沙箱尚未实现，沙箱继续按原计划暂缓。

### 本轮验收

使用 `kernelBrowserHost.ts` 的确定性模拟模型，浏览器检查 1440×960 与 390×844：建议填入、发送、文件写入审批、取消、四个导航入口和工作面板开关通过；窄屏无横向溢出。该验证覆盖界面与 host 调用链，不代表真实模型或桌面发行验收。

## 细节迭代 02：随身工作手册

方向：保留手绘狗的辨识度，用笔记式正文、页边批注和工作手记组织实际操作。品牌角色不替代信息层次；不依赖满屏插画、弹跳动效或假数据制造特色。

参考观察（2026-10-27）：
- [Things](https://culturedcode.com/things/) 官方页面中的应用截图：导航和正文有明确层次，颜色只承担局部识别。借鉴层次，不复刻其图标与布局。
- [Linear](https://linear.app/features) 官方产品页面：标题、说明与细边线形成克制的视觉秩序。仅参考公开页面，不声称审查过登录后的完整产品。

本轮实现：
- 欢迎文案与宋体标题形成手册封面；主头像保留原图，正文使用常规可读字体。
- `ChatWelcome`、`ConversationMessage`、`MessageContent` 分离欢迎、消息操作和 Markdown 渲染。Markdown 经 DOMPurify 标签/属性白名单处理，不加载模型输出中的远程图片。
- 用户消息像页边批注，回答像正文。支持标题、列表、引用、表格、代码和复制回复，复制失败有明确反馈。
- 输入框随内容增长并限制最大高度；阅读旧内容时不强制滚动，提供“回到最新”；侧栏可收起。
- `WorkProgress` 替代默认 App 中的演示舞台，原舞台组件保留为 `/ui/?design=operations` 的独立旧版设计存档。`workSteps` 只合并真实工具调用，同一个调用的开始和结束不重复计数，不把运行完成摘要计作工具操作。
- 审批先呈现操作名称与目标，完整参数可展开；不再截断参数 JSON，所有影响条目可查看。

验证：全量 `bun run check` 通过，179 项包测试及终端 smoke 通过。浏览器实测长 Markdown、复制、回到最新、侧栏切换、审批允许及取消；不可信 HTML 的 script/img/危险链接未进入可执行 DOM。390px 窄屏曾发现代码块撑宽布局，已修正隐式网格列，复测 innerWidth/clientWidth/scrollWidth 均为 390。真实模型、原生打包仍不在本轮证据范围内。

尚未完成的产品设计：任务与设置仍是旧表单/列表风格；运行记录仍偏诊断用途；取消和网络错误文案需要产品化；会话恢复与成果管理需要对应 host 合同。这些是后续迭代范围，不能因为欢迎页与对话已完成就宣布整体 App 设计验收。

## 细节迭代 03：任务、偏好与失败反馈

任务页改为目标清单与结果手记。创建表单只在需要时打开，并聚焦输入；自动生成标题，创建后选中任务；区分待推进/已结束，运行中提供停止，结果复用安全 Markdown。异步失败留在当前页面，重复操作在请求期间禁用。空列表不重复展示两块空状态。

设置页以模型、授权、阅读偏好组织日常配置，协议连接详情与服务/工作区字段折叠展开。当前设置是页面内请求配置，明确提示刷新恢复默认；没有伪装成持久保存。选择预设后手动编辑会回到手动配置；刷新预设不覆盖当前选择。Gemini 因当前内核缺少工具/流式能力，在此智能体设置入口明确标为暂不可选。

错误卡展示可操作的概述与可展开原始原因，不把未知错误武断归为网络失败。主动取消采用正常状态消息，保留取消与真实失败的区别。页面导航回到顶部；390px 任务和高级设置无横向溢出。

真实验收修正了旧任务 API 校验中的合同偏差：后端 TaskRecord 没有 `last_run_id`，Web 不再要求这个字段；审批关联从实际执行步骤取得 run_id。新增真实 Host/Web 的任务创建、列表、详情、执行和取消覆盖。`bun run check` 通过，180 项测试及终端 smoke 通过；浏览器验证创建、执行、筛选、模型手动选择、取消、失败、窄屏与输入焦点。

当前边界：刷新页面后，既有等待审批任务的审批内容尚不能从任务页恢复；未加载审批时展示说明，不提供无效的确认入口。运行记录页仍需完成产品化整理。任务服务依旧是现有单进程实现，本次界面改版不代表后台持久执行或桌面发行已完成。

## 细节迭代 04：工作档案

运行记录改为“索引 + 回顾手册”：左侧以结果摘要、时间和真实状态辨认记录，右侧展示结果正文与重要过程事件。搜索范围明确限定为已加载记录；接口没有用户输入标题，因此不把结果摘要伪装成任务标题。

历史查看只读取选中的运行快照，不写入当前会话的运行关联。工具失败、等待确认、取消和无文字结果分别呈现；只显示服务实际返回的耗时，不生成虚构步骤或成果统计。原始事件保留在折叠详情里，本页请求日志则放回对话的可选诊断区域，并移除预置的假日志。

桌面双栏分别滚动，窄屏堆叠；选择记录后将焦点移到回顾区域。取消使用普通状态说明，搜索无结果时提供明确反馈。删除被替换的 ActionTimeline 组件。

四个主要界面已形成统一的纸张、墨色与琥珀色视觉语言。当前采用 Web UI → Host → Agent SDK 的分层，未来桌面容器复用界面，通过宿主承接原生能力。桌面安装包、会话列表恢复、成果管理和刷新后的任务审批恢复仍需后续实现；原生沙箱继续暂缓。
